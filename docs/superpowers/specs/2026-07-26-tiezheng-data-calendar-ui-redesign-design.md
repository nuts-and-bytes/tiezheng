# 铁证 IRONPROOF · 数据、日历与交互重设计规格

日期：2026-07-26  
状态：设计已确认，等待技术实施计划  
适用仓库：`nuts-and-bytes/tiezheng`

## 1. 目标

本轮改造解决四类问题：

1. 数据页动作标签不完整，动作与 PR 混排，用户难以按训练部位理解记录。
2. 记组数阶段“继续添加动作”的入口不明确，分化训练者容易误以为只能结束打卡。
3. 新动作默认组数仍为 3 组，不符合当前训练习惯。
4. 日历、数据页、部位图标和按钮缺少一致且高效的视觉层级。

成功标准不是“增加更多图表”，而是让用户依次回答：

- 这段时间练了多少？
- 练了哪些部位与动作？
- 最近 12 周是否保持节奏？
- 某个动作是否进步？
- 是否长期忽略了某个部位？

## 2. 已确认的设计方向

- 总体视觉：A「精密锻造」。
- 部位图标：A1「实心部位徽记」。
- 数据页结构：L1「训练叙事」。
- 日历结构：R2「月度轨道」完善版。
- PR：按部位分段、段内排名。
- 动作范围：展示历史上练过的全部动作，按部位分组，并突出今天练过的动作。
- 记组数操作：固定显示“继续添加动作 / 完成打卡”。
- 年度热力图：删除，替换为最近 12 周训练节奏。

## 3. 现状与根因

### 3.1 动作标签缺失

当前数据页的力量趋势调用 `topExerciseIds(items, 5)`：

- 最多只返回 5 个动作；
- 只有存在有效重量和次数的动作才会进入候选；
- 自重、只记次数、只记组数以及低频动作都会从标签区消失。

因此“练过但看不到”不是偶发渲染问题，而是当前选择器的数据口径造成的必然结果。

### 3.2 PR 混排

`prsByExercise` 返回所有动作的历史最佳 e1RM，并按 e1RM 全局降序。`ProfileScreen` 直接渲染该数组，因此腿举、卧推、划船等不同部位动作被放进同一榜单。跨部位名次没有稳定的训练意义。

### 3.3 继续添加动作入口弱

`EditSets` 已存在“上一步”，但它与“完成打卡”组成普通底部按钮行：

- 文案没有表达“继续添加动作”；
- 长动作列表下入口容易脱离主要操作视野；
- 用户完成组数输入后，视觉焦点只剩高亮的“完成打卡”。

### 3.4 默认组数写死为 3

`logDraftStore.addItem` 直接创建 `sets: [{}, {}, {}]`。本轮只改变新添加动作的默认值，不修改已有草稿和历史记录。

### 3.5 数据页层级与年度热力图

当前数据页在周期数字、力量趋势、部位均衡、年度热力、体重与海报入口之间缺乏明确叙事。年度热力图用 365 个极小格子表达训练分布，但无法直接告诉用户近期节奏是否改善，也不能形成下一步行动。

## 4. 数据页信息架构

数据页按以下固定顺序组织：

1. **周期概览**：周 / 月 / 年 / 全部范围下的打卡天数、总组数和自适应负荷指标。
2. **动作趋势入口**：全部历史动作按部位分组；今天练过的动作优先并带“今日”标记。
3. **最近 12 周训练节奏**：展示每周训练天数与总组数。
4. **当前动作趋势**：根据该动作的数据类型展示 e1RM、次数或组数趋势。
5. **部位均衡**：继续展示当前周期各部位组数与距上次训练天数。
6. **体重变化**：仅在存在体重记录时出现。
7. **训练海报与照片时间线**：保留为页面尾部行动区。

### 4.1 动作分组

- 展示所有在训练记录中出现过且仍能取得动作元数据的动作，不设置数量上限。
- 按 `BODY_PARTS` 的稳定顺序分组：胸、肩、背、腿、手臂、核心、有氧。
- 只渲染有动作的部位分组。
- 分组内排序：今天练过的动作优先，其余按最近训练日期降序；同日并列时按动作名称稳定排序。
- 今天练过的动作同时使用实心徽记、部位色和“今日”文字，不只依赖颜色。
- 当前动作不在新列表中时，优先回退到今天最近练过的动作；今天无训练则回退到最近一次练过的动作。

### 4.2 单动作趋势自适应

每个动作独立判断可用数据层级：

1. 存在有效重量与次数：显示最近 12 次估算 1RM。
2. 没有有效重量，但存在次数：显示每个训练日的最佳次数。
3. 只有组数：显示每个训练日的有效组数。

趋势标题和单位必须随口径变化，不能把次数或组数伪装成力量趋势。只有一个数据点时继续使用数字降级态，不绘制空折线图。

### 4.3 最近 12 周训练节奏

- 固定包含当前自然周和之前 11 个自然周，周一为每周起点。
- 每周柱高表示总组数；柱顶数字或点标表示训练天数。
- 当前周明确高亮，并标注“本周”。
- 没有训练的周仍保留基线位置，避免时间轴断裂。
- 图表只回答训练节奏，不再混入动作趋势或部位分布。

## 5. PR 分组

PR 保留在“我的”页面，改为部位分段：

- 每个有 PR 数据的部位形成独立列表并带 A1 实心徽记。
- 部位顺序沿用 `BODY_PARTS`，不按 e1RM 跨部位重排。
- 部位内部按 e1RM 降序；同值时按日期新到旧，再按动作名稳定排序。
- 每个部位第一名使用热源色高亮，但不再显示跨部位全局名次。
- 说明文案改为“按预估 1RM（Epley）· 每个部位独立比较”。
- 没有任何带重量动作时沿用现有空态。

## 6. 打卡流程

### 6.1 默认四组

- 新添加动作创建 4 个空组。
- 旧草稿保持原组数，不在加载时自动补齐。
- 用户仍可自由增加和删除组。

### 6.2 继续添加动作

- 记组数页面底部使用固定操作栏，并适配 iOS safe area。
- 左侧次按钮文案为“继续添加动作”，返回动作选择步骤。
- 右侧主按钮为“完成打卡”。
- 返回后保留已选择动作、已填写重量与次数以及部位选择。
- 再次进入记组数页面时，已有数据不得重置或重复添加默认组。
- 动作列表滚动区域和固定操作栏必须使用明确的 `min-height: 0` 与底部留白，避免最后一个动作被操作栏遮挡。

## 7. 月度轨道日历

传统 7×6 月历替换为“31 天训练轨道 + 选中日信息卡”。

### 7.1 轨道

- 每个自然日占一个垂直刻度。
- 未训练日显示短中性刻度。
- 训练日柱高由当天组数决定，使用当月 p90 封顶，避免单个极端训练日压扁其余柱。
- 颜色表示部位；一天多部位时最多显示两种分段色，复用现有 `cellParts` 规则。
- 选中日期使用高对比轮廓并显示日号。
- 轨道提供 1、8、15、22、月末等定位标签，不逐日堆叠文字。

### 7.2 默认选择

- 当前月：默认选择不晚于今天的最近训练日。
- 历史月份：默认选择该月最后一个训练日。
- 未来月份或整月无训练：显示月度空态，不伪造选中记录。

### 7.3 信息卡

信息卡展示：

- 相对日期主标题；
- 具体月日副标题；
- 全部训练部位；
- 动作数、总组数与可用时的训练容量；
- 当天动作列表与各动作组数；
- 进入完整日记录的入口。

相对日期规则以周一为一周起点：

- 目标日期在当前自然周：`本周六`。
- 目标日期在上一自然周：`上周三`。
- 早于上一自然周且同年：`7月3日`。
- 跨年：`2025年12月28日`。

具体日期始终保留在副标题中，避免相对日期失去锚点。

### 7.4 可访问性

- 每个训练柱是可聚焦按钮，名称包含日期、全部部位和总组数。
- 空刻度不进入键盘焦点顺序。
- 选中状态同时使用轮廓、`aria-pressed` 和文字，不只靠颜色。

## 8. 视觉系统

### 8.1 精密锻造

- 保留暗色工业基底、热源橙、部位色和数字展示字体。
- 减少实心卡片、重复边框和无意义阴影，优先使用字号、间距与蚀刻线建立层级。
- 数据界面的标题直接表达问题，例如“最近 12 周训练节奏”“动作趋势”，不使用泛化的“分析”“洞察”。

### 8.2 A1 实心部位徽记

- 七个部位各有两两可区分的实心轮廓。
- 12px 时仍可辨认，40px 时不暴露多余细节。
- 同一 SVG 真相源用于部位选择、动作分组、PR、日历和图例。
- 形状必须避免与搜索、播放、设置等通用功能图标混淆。

### 8.3 按钮系统

建立统一按钮组件与三种层级：

- `primary`：热源渐变，用于每屏唯一主操作。
- `secondary`：金属发丝描边，用于返回、继续添加、次级确认。
- `tertiary`：无容器文字按钮，用于关闭、移除和低风险操作。

全部层级必须具备默认、按压、键盘焦点、禁用和加载状态。按钮文字始终由 HTML 渲染。

## 9. GPT 生图与资产落地

GPT 生图用于探索造型，不直接替代可访问、可缩放的 UI 代码。

生成三组项目参考资产：

1. 七个部位实心徽记概念组。
2. 四个底部导航图标与铁证品牌钢印概念组。
3. 主按钮、次按钮、信息卡的精密锻造材质与光影参考。

生成结果保存到项目设计参考目录，记录最终提示词。经视觉筛选后：

- 图标重绘为内联 SVG；
- 按钮和表面用 CSS token 实现；
- 不把带文字的生成图片用于按钮；
- 不引入依赖网络的运行时图片；
- 项目在离线 PWA 状态下保持完整可用。

## 10. 代码边界

计划新增或重构的主要边界：

- `src/lib/stats.ts`：动作分组、单动作趋势口径、12 周训练节奏纯函数。
- `src/lib/dates.ts`：相对训练日期纯函数。
- `src/screens/stats/`：拆分周期概览、动作分组、节奏图、动作趋势与部位均衡。
- `src/screens/calendar/`：月度轨道和信息卡。
- `src/screens/profile/ProfileScreen.tsx`：PR 分组展示。
- `src/screens/log/LogFlow.tsx`：固定操作栏和“继续添加动作”。
- `src/stores/logDraftStore.ts`：新动作默认四组。
- `src/components/PartIcon.tsx`：A1 实心徽记与导航图标。
- `src/components/Button.tsx`：统一按钮层级和状态。

不修改 IndexedDB schema，不迁移历史训练记录，不改变导入导出格式。

## 11. 错误与边界状态

- 动作元数据暂未加载时保持稳定骨架，不显示错误名称或跳动排序。
- 选中动作被删除或不再可用时，按既定回退顺序选择下一动作。
- 12 周完全无数据时显示训练入口，不绘制空坐标轴。
- 月度轨道没有记录时显示“这个月还没有一条铁证”，同时保留月份切换。
- 计算容量所需字段缺失时隐藏容量格，不显示 0kg 冒充有效结果。
- 固定操作栏在提交期间禁用所有重复提交入口，保留现有重入门闩。

## 12. 测试与验收

### 12.1 纯函数测试

- 全部历史动作按部位分组，不受 5 个上限影响。
- 今日动作优先、最近日期排序和稳定并列规则。
- 单动作趋势在 e1RM、次数、组数三层之间正确降级。
- 最近 12 周边界、跨年周与空周。
- PR 分组、段内排序和空部位省略。
- 相对日期在本周、上周、更早、跨年和周一边界的输出。
- 月度轨道默认选择与 p90 柱高封顶。

### 12.2 组件测试

- 所有练过的动作标签均能出现并可选择。
- 今天动作带文字标记，不只改变颜色。
- PR 按部位形成独立列表。
- 新动作默认 4 组，旧草稿不被补组。
- “继续添加动作”返回后保留组数，再进入时不重置。
- 月度轨道点击训练柱后信息卡更新。
- 统一按钮的加载、禁用和焦点状态。

### 12.3 视觉与流程验收

- 320px、390px、430px 三种手机宽度。
- iOS safe area 下固定操作栏不遮挡最后一组。
- 部位徽记在 12px、18px、40px 均可区分。
- 数据页各区块的标题、口径和图表形成顺序关系。
- 从选择部位到继续添加动作、完成打卡的完整浏览器流程。
- 月度轨道的月份切换、默认选中、相对日期和空态。

### 12.4 完成门禁

提交前必须通过：

- 相关 RED-GREEN-REFACTOR 测试；
- 完整 `npm test`；
- `npm run typecheck`；
- `npm run build`；
- 浏览器关键流程与手机尺寸视觉验收；
- 任务范围 diff 检查，确保没有提交用户无关改动或 `.superpowers/` 临时文件。
