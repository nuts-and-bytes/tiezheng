# 铁证 JSON 数据恢复设计

**日期：** 2026-08-04
**状态：** 已确认，待实现
**目标：** 让用户把铁证导出的 JSON 备份安全恢复到当前版本，并清楚理解“安全合并”与“完整覆盖”的区别。

## 范围

本期支持铁证自身导出的 JSON 文件。恢复内容包括训练日、训练动作、每组重量与次数、动作库、体重记录和个人设置。CSV 继续只用于查看和分析，不作为恢复格式。

照片、未完成的打卡草稿、运行日志和已软删除记录不在 JSON 备份中。本次恢复不导入、删除或修改设备上现有照片。

## 用户流程

1. 用户在“我的 → 数据导出”区域点击“从 JSON 恢复”。
2. 用户选择一个 `.json` 文件。
3. 应用完整读取并校验文件，但不写入数据库。
4. 应用显示备份时间、训练天数、动作数、训练组数和体重记录数。
5. 用户选择“安全合并”或“完整覆盖”。
6. 用户确认后，应用在单个 IndexedDB 事务中完成恢复。
7. 恢复成功后页面重新加载并显示结果；失败时事务回滚，当前数据保持不变。

## 恢复方式

### 安全合并（默认、推荐）

界面说明：

> 保留当前记录，并加入备份数据。同一天发生冲突时，以备份记录为准。

- 保留当前数据库中未与备份冲突的训练和体重记录。
- 训练以日期为业务唯一键。备份中某一天存在训练时，该日当前训练及其动作明细由备份版本整体替换，避免同一天出现两次打卡或混合两套动作。
- 体重记录同样按日期处理冲突，备份版本优先。
- 自定义动作按 ID 合并；备份中同 ID 的自定义动作优先。
- 当前版本的系统预设动作定义优先，旧备份不得覆盖新版名称、部位或重量模式。
- 个人昵称和每周目标使用备份值；备份缺少的可选字段保留当前值。
- 重复导入同一备份不得制造重复训练、动作或体重记录。

### 完整覆盖

界面说明：

> 用备份替换当前训练、动作、体重和个人设置。覆盖前会自动下载当前数据备份。

- 用户选择“完整覆盖”后，应用先生成并下载一份当前 JSON 备份。
- 自动备份下载成功后，才允许用户再次点击“确认覆盖”。下载失败时不得进入覆盖事务。
- 覆盖事务清除当前训练、训练明细、体重记录、自定义动作和个人设置，再写入备份内容。
- 当前版本的系统预设动作重新作为基础写入；备份仅恢复自定义动作及历史训练对动作的有效引用。
- 照片表不进入事务清除范围，设备上的照片保持不变。

## 备份格式与兼容性

新导出的顶层 JSON 增加：

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-08-04T00:00:00.000Z"
}
```

- 缺少 `schemaVersion` 的现有备份按版本 0 读取。
- 版本 0 允许动作缺少 `loadMode`，缺失时使用 `external`；当前系统预设动作仍使用应用内最新定义。
- 高于应用所支持版本的备份拒绝导入，并提示“备份来自更新版本，请先更新铁证”。
- 导入器只接受明确白名单字段，不把未知字段写入数据库。

## 校验规则

文件在任何数据库写入前完成结构、范围和引用校验：

- 文件必须是合法 JSON，顶层对象和各数据表必须是预期类型。
- ID 必须是非空字符串；日期必须是有效的 `YYYY-MM-DD`。
- 部位只能是当前七个 `BodyPart` 值；重量模式只能是 `external` 或 `assistance`。
- 组数数组不能为空；重量、次数和体重必须满足应用现有数值范围并且是有限数值。
- 每个训练明细必须引用备份内或当前系统预设中的有效动作，每个训练 ID 必须存在。
- 同一备份内不得出现重复 ID、重复训练日期或重复体重日期。
- 备份文件大小上限为 10 MB；超过上限直接拒绝。
- 任一校验失败都显示具体、可理解的错误，不产生部分恢复。

## 模块边界

- `exportData.ts`：继续负责生成备份，新增 `schemaVersion`。
- `importData.ts`：负责解析、版本兼容、白名单清洗、引用校验、预览统计和事务恢复；不包含界面状态。
- `ProfileScreen.tsx`：负责选文件、展示预览、选择恢复方式、二次确认和结果提示。
- 数据库仓储与预设动作数据继续作为当前系统定义的唯一来源。

## 界面

“数据导出”区域增加“从 JSON 恢复”按钮和隐藏文件选择器。选择文件后打开恢复面板：

- 顶部显示文件名、备份时间与五项统计。
- 中部显示两张单选卡，默认选中“安全合并（推荐）”。
- 每张卡直接展示保留、替换和冲突处理规则，不依赖帮助页。
- 固定提示：“照片不包含在备份中，本次恢复不会改动本机照片。”
- “完整覆盖”使用警示色，并通过独立的“确认覆盖”步骤防止误触。
- 恢复期间禁用文件选择、模式切换和提交按钮，防止重复操作。
- 成功提示为“已恢复 X 天训练记录”；失败提示区分文件损坏、版本过新、内容不合法、自动备份失败和数据库恢复失败。

## 原子性与失败处理

- 合并和覆盖都在包含 `workouts`、`workoutItems`、`exercises`、`weightLogs`、`profile` 的单个 Dexie 读写事务中执行。
- 照片表不参与恢复事务。
- 解析、校验和完整覆盖前的自动备份发生在写事务之前。
- 事务抛错时由 Dexie 回滚全部写入，界面保留预览以便用户修正或重试。
- 错误日志不得记录备份正文、训练备注、昵称或其他用户数据。

## 验收与测试

- 新导出文件包含 `schemaVersion: 1`，当前旧版无版本备份仍可恢复。
- 安全合并保留不冲突记录，并以备份整体替换冲突日期。
- 完整覆盖先成功下载当前备份，再替换规定的数据表。
- 系统预设动作不会被旧备份降级，自定义动作与 `assistance` 重量模式可恢复。
- 损坏 JSON、未来版本、非法日期、越界数值、重复键和断裂引用均在写入前拒绝。
- 事务中途失败时数据库内容完全不变。
- 同一备份重复合并两次结果一致。
- 两种模式均不改动照片表。
- 界面正确解释两种模式、显示预览统计、阻止重复提交并给出成功或分类错误提示。
- 单元测试、组件测试、完整测试套件、类型检查和生产构建全部通过。
